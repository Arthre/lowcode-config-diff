# 完成验证

> **触发时机**：声称工作完成、已修复、测试通过之前。 **核心规则**：没有新鲜的验证证据，不做任何完成声明。 **借鉴来源**：[Superpowers `verification-before-completion`](https://github.com/obra/superpowers/blob/main/skills/verification-before-completion/SKILL.md)

## 铁律

```
没有新鲜验证证据，就不声称完成
```

如果你在本轮消息中还没运行验证命令，就不能声称它通过了。

违反字面规则就是违反精神规则。

## 验证流程（门控函数）

```
声称任何状态之前：

1. 确定：什么命令能证明这个声明？
2. 运行：执行完整命令（新鲜的、完整的）
3. 阅读：完整输出，检查退出码，统计失败数
4. 验证：输出是否支持声明？
   - 不支持 → 报告实际状态和证据
   - 支持 → 带证据做出声明
5. 然后才能：声称完成

跳过任何一步 = 说谎，不是验证
```

## 本仓库验证命令

按改动风险选用；声称完成前至少跑通与本次改动相关的一项，并阅读完整输出。

| 场景                  | 命令                                       | 通过标准                         |
| --------------------- | ------------------------------------------ | -------------------------------- |
| 代码风格 / 静态规则   | `pnpm lint`                                | exit 0                           |
| 自动修复后复检        | `pnpm lint:fix` 后再 `pnpm lint`           | exit 0                           |
| 类型检查 + 生产构建   | `pnpm build`（`vue-tsc -b && vite build`） | exit 0                           |
| 单元测试              | `pnpm test:run`                            | exit 0，失败数为 0               |
| 覆盖率（按需）        | `pnpm test:coverage`                       | exit 0；覆盖率门槛以任务要求为准 |
| 仅本地预览构建产物    | `pnpm preview`（先成功 `pnpm build`）      | 服务可启动且关键路径可访问       |
| 格式化（非替代 lint） | `pnpm format`                              | 不单独作为“完成”证据             |

不要使用其他仓库遗留命令（如 `pnpm check:type`、`pnpm dev:antd`）冒充验证。

## 常见声明与所需验证

| 声明       | 需要的验证              | 不充分的                         |
| ---------- | ----------------------- | -------------------------------- |
| Lint 通过  | `pnpm lint`：exit 0     | 之前的运行结果、"应该通过"       |
| 构建成功   | `pnpm build`：exit 0    | 仅 Lint 通过、"日志看起来没问题" |
| 测试通过   | `pnpm test:run`：0 失败 | 之前的运行结果、未跑相关用例     |
| Bug 已修复 | 复现原症状并确认消失    | 代码改了，假设修好了             |
| 需求已满足 | 逐项对照检查清单        | Lint/构建通过 ≠ 需求满足         |
| 子代理完成 | 检查 VCS diff 确认变更  | 子代理报告"成功"                 |

## 回归测试验证（TDD Red-Green）

```
✅ 写测试 → 运行（通过）→ 撤销修复 → 运行（必须失败）→ 恢复 → 运行（通过）
❌ "我写了回归测试"（没有 red-green 验证）
```

## 子代理委派验证

```
✅ 子代理报告成功 → 检查 VCS diff → 验证变更 → 报告实际状态
❌ 信任子代理报告
```

## 危险信号 — 停下来

- 用"应该""大概""看起来""似乎"等词
- 验证前表达满意（"完成了！""没问题！""很好！"）
- 准备提交/推送/PR 但没运行验证
- 依赖部分验证
- 信任子代理的成功报告
- 想"这次算了"
- 累了想结束工作
- **任何暗示成功但未运行验证的措辞**

## 借口 vs 现实

| 借口             | 现实                 |
| ---------------- | -------------------- |
| "应该没问题了"   | 运行验证命令         |
| "我很确定"       | 确信 ≠ 证据          |
| "Lint 通过了"    | Lint ≠ 编译 ≠ 运行时 |
| "子代理说成功了" | 独立验证 diff 和测试 |
| "就这一次"       | 没有例外             |

## 适用时机

**始终在以下情况之前：**

- 任何成功/完成声明的变体
- 任何满意表达
- 任何关于工作状态的正向陈述
- 提交、PR 创建、任务完成
- 进入下一任务
- 委派给子代理之后

## 底线

运行命令。阅读输出。**然后才能**声称结果。

不可商量。
