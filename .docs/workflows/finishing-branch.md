# 分支收尾

> **触发时机**：实现完毕，完成验证通过，准备合并时。 **流程**：完成验证 → 提供选项 → 执行选择 → 清理。 **借鉴来源**：[Superpowers `finishing-a-development-branch`](https://github.com/obra/superpowers/blob/main/skills/finishing-a-development-branch/SKILL.md)

## 流程

### 第一步：完成验证

按 [完成验证](./verification.md) 执行与改动匹配的命令（至少 `pnpm lint` 与相关 `pnpm test:run`；涉及类型/构建风险再 `pnpm build`）。

- 验证失败 → **停止**，不进入下一步

### 第二步：确定基础分支

确认当前分支从哪个分支分出（通常是 `main` 或 `master`）。

### 第三步：提供 4 个选项

```
实现完毕。接下来怎么做？

1. 本地合并回 <基础分支>
2. 推送并创建 Pull Request
3. 保留分支现状（稍后处理）
4. 丢弃这次工作
```

### 第四步：执行选择

| 选项        | 合并 | 推送 | 保留工作树 | 清理分支  |
| ----------- | ---- | ---- | ---------- | --------- |
| 1. 本地合并 | ✓    | -    | -          | ✓         |
| 2. 创建 PR  | -    | ✓    | ✓          | -         |
| 3. 保持现状 | -    | -    | ✓          | -         |
| 4. 丢弃     | -    | -    | -          | ✓（强制） |

**丢弃必须确认**：列出将删除的分支、提交、工作树，要求用户明确确认。

## 安全规则

- 不在验证失败的情况下合并
- 合并后在合并结果上再按 `verification.md` 跑一次验证
- 不确认就不删除工作
- 不未经请求就 force-push
