# 测试驱动开发（TDD）

> **触发时机**：实现任何功能或修复 bug 时。 **核心规则**：没有失败测试，不写实现代码。 **借鉴来源**：[Superpowers `test-driven-development`](https://github.com/obra/superpowers/blob/main/skills/test-driven-development/SKILL.md)

## 铁律

```
没有失败测试，就不写生产代码
```

先写了代码？**删除它，从头开始。**

- 不要保留为"参考"
- 不要"改编"它来写测试
- 不要看它
- 删除就是删除，从测试重新实现

违反字面规则就是违反精神规则。"就这一次跳过 TDD"？停下来，那是合理化。

## 本仓库说明

单元测试使用 **Vitest + happy-dom + @vue/test-utils**：

- 命令：`pnpm test`（监听）/ `pnpm test:run`（CI/完成验证）/ `pnpm test:coverage`
- 用例放在 `src/**/*.{spec,test}.ts`；`describe` / `it` 说明用中文（见 `.cursor/rules/unit-test-chinese.mdc`）
- 平凡单行修复可按 `AGENTS.md` 简单改动路径处理，但仍需验证

## Red-Green-Refactor 循环

```
RED（写失败测试）
  → 确认失败 → 失败原因正确？
      ├─ 是 → GREEN（写最小实现）
      │        → 确认通过 → 全部通过？
      │            ├─ 是 → REFACTOR（清理）→ 保持绿色 → 下一轮
      │            └─ 否 → 修复实现（不改测试）
      └─ 否 → 修复测试
```

### RED — 写失败测试

- 一个测试只测一个行为
- 测试名描述行为（不是 `test1`）
- 用真实代码，避免 mock（除非不可避免）
- 写**一个**最小测试，展示应该发生什么

### 确认 RED

**必做。不可跳过。**

- 运行测试，确认失败
- 确认是因为功能缺失而失败（不是拼写错误）
- 如果测试直接通过 → 说明测的是已有行为，改测试
- **如果你没看到测试失败，就不知道它测的是不是正确的东西**

### GREEN — 最小实现

- 写**刚好**能让测试通过的代码
- 不加额外功能
- 不重构其他代码
- 不"顺便改进"

### 确认 GREEN

**必做。**

- 所有测试通过
- 输出干净（无错误、无警告）

### REFACTOR — 清理

仅在绿色状态下：

- 消除重复
- 改善命名
- 提取辅助函数
- 保持测试绿色

## Bug 修复流程

1. 写能复现 bug 的失败测试
2. 确认测试失败
3. 修复 bug
4. 确认测试通过
5. 测试证明了修复，也防止了回归

## 测试反模式（避免）

| 反模式                   | 正确做法                          |
| ------------------------ | --------------------------------- |
| 测试实现细节而非行为     | 测试用户可见的行为和公共接口      |
| 一个测试测多个行为       | 一个测试一个行为                  |
| 过度 mock 导致测试无意义 | 优先真实代码，mock 仅在不可避免时 |
| 测试通过但不知道测了什么 | 必须先看到失败                    |
| 后补测试直接通过         | 后补的测试证明不了新行为          |

## 危险信号 — 停下来重新开始

- 先写了代码再写测试
- 测试直接通过（没看到失败）
- 不清楚测试为什么失败
- 想"这次就不测了"
- 想"手动测过了，不需要自动化测试"

**以上任何情况：删除代码，从测试开始重新来。**

## 常见借口 vs 现实

| 借口               | 现实                               |
| ------------------ | ---------------------------------- |
| "太简单不需要测试" | 简单代码也会坏。测试只需 30 秒     |
| "先写完再补测试"   | 后补的测试直接通过，证明不了什么   |
| "TDD 太慢"         | TDD 比调试快。务实 = 先测试        |
| "手动测试更快"     | 手动测试不可重复，改了代码要重新测 |
