## 背景与目标

在已解析的 TEST / PROD `Config` 上计算叶子差异，并为每叶写入**默认选边**。本切片不实现 Merge，不做 UI。

---

## 需求变更

### + 新增

- [diffConfig]：根可为 object 或 array；对 object 递归产出叶子；根或子路径上的 array 按整段比较；只产出叶子 `added` / `removed` / `modified`。
- [默认 side]：按总览表写入 `side`（见下）；不再使用「默认不选 / selected=false」语义。
- [类型变迁]：同 path 类型不同 → 一个 `modified`，整段替换语义（不互递归）。
- [数组整段]：deep-equal 整段比较；禁止按 index 猜对象身份。
- [缺 key vs null]：按类型表区分 added/removed；双方 null 无 Diff。

### ~ 修改（相对早期草案）

- [选择模型]：从 `selected: boolean` 改为 `side: 'test' | 'prod'`。
- [默认]：从「全不选」改为「modified/added→test，removed→prod」。

### 非目标（本切片）

- `mergeConfig`、选边 UI、Diff 树
- 数组 Identity 自动猜测（可留扩展点，V0.1 不走 identity）
- 用户可见的「Diff Path 冲突」流程

## 接口与规则

```ts
type DiffType = 'added' | 'removed' | 'modified';
type DiffSide = 'test' | 'prod';

interface DiffItem {
  id: string;
  path: string[];
  type: DiffType;
  testValue?: JsonValue;
  prodValue?: JsonValue;
  /** 默认选边；UI 可改，merge 按此组装 */
  side: DiffSide;
  valueType?: 'object' | 'array' | 'string' | 'number' | 'boolean' | 'null';
  arrayMode?: 'whole';
}

diffConfig(testConfig: Config, prodConfig: Config): DiffItem[]
```

**类型含义：**

| type     | 含义             |
| -------- | ---------------- |
| added    | TEST 有、PROD 无 |
| removed  | TEST 无、PROD 有 |
| modified | 双方都有且值不等 |

示例：TEST 有 `table`、PROD 无 → **`added`**（不是 removed）。

**默认 side：**

| type     | 默认 side                      |
| -------- | ------------------------------ |
| modified | `test`                         |
| added    | `test`                         |
| removed  | `prod`（仅 PROD 有，默认带上） |

- 仅 `form.name.required` 不同时，只产出该 path。
- 引擎不产出纯容器中间节点。
- Diff 不修改输入对象。

**建议文件：** `src/core/diff.ts`、`src/core/array.ts`。

## 验收清单

1. 完全相同 → 空列表。
2. 根为 object 时：根属性 added / removed / modified 分类正确。
3. 根均为 array 且内容不同 → path `[]` 上一个整段 diff（默认 side 按 modified）。
4. 根类型不同（object↔array）→ path `[]` 上一个 modified（类型变迁）。
5. 深层 object 最小叶子；string/number/boolean/null 修改。
6. 空 object / 空 array；子路径数组整段 diff；对象数组不按 index 误匹配。
7. 默认 side：modified/added 为 `test`，removed 为 `prod`。
8. 输入未被修改；相关单测通过。
