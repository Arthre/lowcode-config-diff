## 一句话语义（唯一口径）

> 计算 TEST 与 PROD 的叶子差异；每个差异由用户选择采用 **TEST 侧或 PROD 侧**；按选边组装最终 JSON。日常以测试配置推进：默认多数取 TEST，**仅 PROD 有的 key 默认取 PROD（保留生产独有）**；生产与其它差异是否保留由人决定。

各切片不得改写此口径；发现冲突时回写本总览。

---

## 背景与 V0.1 目标

测试/生产各自维护低代码 JSON；生产常有紧急直改。V0.1 纯前端：导入 TEST/PROD → Diff → **逐叶选边** → 合并双方 → 复制/下载。不连库、不连平台、不发布。

**整体成功标准：** Core 单测可证 Diff/Merge；UI 走通主路径；原始输入不被改；用户 JSON 不出域。

---

## 产品原则

1. 工具主目的是**解决 TEST 与 PROD 的配置差异**；最终产出是合并双方差异后的一份 JSON。
2. 出现差异时由用户选择采用哪一方（每叶 **TEST | PROD**）。
3. **默认以 TEST 为主**：`modified` 与「仅 TEST 有」默认选 TEST；**「仅 PROD 有」默认选 PROD（默认带上）**。
4. 日常以测试配置推进，生产差异由人决定是否保留。
5. **Diff UI 默认只展示有差异的节点**；无差异处默认隐藏，可通过选项开启「显示无差异」以便对照上下文。
6. 数组无法可靠识别元素身份时整段比较，不猜。
7. Diff Engine 与 UI 解耦；优先正确性。
8. 用户 JSON 默认只在客户端处理；不为未来扩展提前做复杂功能。

## 全局口径摘要

| 概念        | 约定                                                       |
| ----------- | ---------------------------------------------------------- |
| `added`     | TEST 有、PROD 无                                           |
| `removed`   | TEST 无、PROD 有                                           |
| `modified`  | 双方都有且不等（含类型变迁）                               |
| 选边        | 每叶 `side: 'test' \| 'prod'`，不是「是否应用」            |
| 默认 side   | `modified` / `added` → `test`；`removed` → `prod`          |
| 选 TEST     | `modified`→TEST 值；`added`→写入；`removed`→不写入         |
| 选 PROD     | `modified`→PROD 值；`added`→不写入；`removed`→写入 PROD 值 |
| 叶子        | 引擎只产出有差异的叶子；父节点仅展示/批量设 side           |
| Diff 展示   | 默认仅差异树；选项可开启显示无差异节点（只读对照，无选边） |
| path        | 内部 `string[]`；展示可 `a.b.c`                            |
| 数组        | V0.1 一律整段 deep-equal；不按 index 猜身份                |
| 相等        | 语义深相等，忽略 object key 顺序；数组顺序敏感             |
| 配置根      | object 或 array（拒绝顶层 null / primitive）               |
| 默认合并    | ≡ TEST ∪「仅 PROD 有」（冲突取 TEST）                      |
| 全部选 TEST | ≡ TEST                                                     |
| 全部选 PROD | ≡ PROD                                                     |

组装无「单一不可变基线」的产品叙事；实现可 `deepClone(TEST)` 为脚手架，再按各叶 `side === 'prod'` 套用 PROD 语义（详见 M3）。

## 架构与目录

```text
[TEST]──parse──┐
               ├─diff──► DiffItem[]（含默认 side）──UI 选边──► leavesWithSide
[PROD]──parse──┘                                              │
                                                              ▼
                              mergeConfig(test, prod, leaves)──► format / 复制下载（UI）
```

```text
src/core/     types, path, equal, parse, format, diff, merge
src/components/  JsonEditor, DiffTree, MergePreview …
src/views/    单页主流程
```

Core **禁止**依赖 Vue / Pinia / DOM。数组整段比较逻辑收拢在 `diff.ts`（不另建 `array.ts`）。

## 实现约束（全局）

- 复用 Vue3 + TS + Vite + Vitest + UnoCSS；无理由不引入大型新依赖。
- 可用已有 Pinia/composable；禁止第二套状态方案。
- 输出必须是纯 JSON；按叶子选边合并，默认以 TEST 为主（仅 PROD 有默认保留）。
- 歧义时保持简单并回写规格。
- 完成验证：Core 用 `pnpm test:run`；UI 手工走主路径；按需 lint/build。
